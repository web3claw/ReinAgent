# Linux CIFS 网络共享盘环境下 ReinAgent 编译与运行解决方案

- **记录日期**：260721 (2026-09-21)
- **目标工程**：ReinAgent (Tauri v2 + React 19 + TypeScript + Bun)
- **环境信息**：Linux x86_64, CIFS/SMB 挂载盘 (`//192.168.3.27/DevCode`)

---

## 一、问题背景与错误现象

在 Linux 环境下直接进入挂载的 Windows 网络共享目录运行 ReinAgent 时，遇到两个阻断性问题：

### 问题 1：前端依赖安装报错 `EPERM`
执行 `bun install` 时直接报错中断：
```text
bun install v1.4.2 (744846f84)
error: Failed to link @anthropic-ai/sdk: EPERM
error: Failed to link @earendil-works/pi-ai: EPERM
error: Failed to link @tauri-apps/cli: EPERM
error: Failed to link nanoid: EPERM
error: Failed to link rolldown: EPERM
error: Failed to link typescript: EPERM
error: Failed to link vite: EPERM
error: Failed to link yaml: EPERM
```

### 问题 2：Rust/Tauri 编译链接报错 `neither ET_REL nor LLVM bitcode`
执行 `cargo build` 或 `cargo tauri dev` 时，链接阶段大面积报错退出：
```text
rust-lld: warning: .../libsyn-...rlib: archive member '...rcgu.o' is neither ET_REL nor LLVM bitcode
rust-lld: error: undefined hidden symbol: <syn::item::ItemFn as quote::to_tokens::ToTokens>::to_tokens::{closure#0}
rust-lld: error: undefined hidden symbol: core::hint::unreachable_unchecked::precondition_check
...
collect2: error: ld returned 1 exit status
error: could not compile `cssparser-macros` (lib) due to 1 previous error
error: could not compile `derive_more-impl` (lib) due to 1 previous error
```

## 二、根本原因深度剖析

两个问题本质上均由 **Linux 内核 CIFS 驱动在 Windows SMB 网络共享盘上的文件系统限制** 引发：

### 1. 软链接（Symlink）不支持导致 `Failed to link: EPERM`
- **机制**：带有 `bin` 命令行声明的 npm 包（如 `vite`、`tauri`），包管理器在安装时必须在 `node_modules/.bin/` 目录下通过系统调用 `symlink` 创建指向执行脚本的软链接。
- **原因**：当前 CIFS 挂载默认未启用 Unix 扩展（挂载选项包含 `nounix`、`symlink=native`），Linux 内核拒绝在 SMB 盘上创建 POSIX 符号链接，返回 `EPERM`。

### 2. SMB 缓存/mmap 并发写失效导致编译产物全为 `0x00` 坏道
- **机制**：Rust 编译器（rustc）进行多代码生成单元（CGU）并发编译时，会高频使用内存映射（`mmap`）、随机写入与文件截断（`ftruncate`）生成大量的 `.rcgu.o` 目标文件，并用 `ar` 归档为 `.rlib`。
- **原因**：通过十六进制工具提取报错的 `syn-...rcgu.o` 文件分析，发现整整 678,808 字节**全部是 `0x00`（全 0 坏道）**。在网络盘多线程写密集场景下，Linux CIFS 缓存未及时刷盘就完成了归档，导致生成的目标文件实际为空坏道。链接器读取到一堆 `00 00 00` 无法识别 ELF 文件头，抛出 `neither ET_REL nor LLVM bitcode`。

---

## 三、解决方案与架构设计

为了**不破坏原有网络共享盘上的代码文件与现存 Windows 依赖**，采取「**源码保留在共享盘，易损产物重定向到 Linux 本地磁盘**」的隔离运行策略：

1. **依赖重定向**：将 `node_modules` 安置于 Linux 本地高速文件系统 `/tmp/reinagent/node_modules`（原生支持软链接）。
2. **构建缓存重定向**：利用 Cargo 官方原生环境变量 `CARGO_TARGET_DIR="/tmp/reinagent/target"`，将所有 Rust 编译产物写入本地，彻底杜绝 CIFS 写穿全 0 坏道问题，且编译提速数倍。
3. **前端热更新联动**：在 `/tmp/reinagent` 建立对源码 `src`、`public` 的符号链接，并在本地 Vite 配置注入 `resolve.preserveSymlinks: true`，确保修改共享盘源码时 Vite HMR 热重载依然 100% 实时生效。

## 四、启动脚本实现：`run-linux.sh`

项目根目录下已创建专属启动脚本 `run-linux.sh`：

```bash
#!/usr/bin/env bash
set -e

PROJECT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
WORK_DIR="/tmp/reinagent"
TARGET_DIR="$WORK_DIR/target"

echo "=== [1/4] 准备 Linux 本地运行环境 ($WORK_DIR) ==="
mkdir -p "$WORK_DIR" "$TARGET_DIR"

# 同步包描述文件
cp "$PROJECT_DIR/package.json" "$WORK_DIR/package.json"
if [ -f "$PROJECT_DIR/bun.lock" ]; then
    cp "$PROJECT_DIR/bun.lock" "$WORK_DIR/bun.lock"
fi

# 安装 Linux 平台原生依赖（避免 CIFS 软链接限制）
if [ ! -d "$WORK_DIR/node_modules" ]; then
    echo "正在安装 Linux 依赖到 $WORK_DIR..."
    (cd "$WORK_DIR" && bun install)
fi

# 链接工程文件并配置 Vite（启用 preserveSymlinks）
ln -sfn "$PROJECT_DIR/src" "$WORK_DIR/src"
ln -sfn "$PROJECT_DIR/public" "$WORK_DIR/public"
ln -sfn "$PROJECT_DIR/tsconfig.json" "$WORK_DIR/tsconfig.json"
ln -sfn "$PROJECT_DIR/tsconfig.node.json" "$WORK_DIR/tsconfig.node.json"
cp -f "$PROJECT_DIR/index.html" "$WORK_DIR/index.html"

node -e '
const fs = require("fs");
let cfg = fs.readFileSync(process.argv[1], "utf8");
if (!cfg.includes("preserveSymlinks")) {
    cfg = cfg.replace("plugins: [react()],", "plugins: [react()],\n  resolve: { preserveSymlinks: true },");
}
fs.writeFileSync(process.argv[2], cfg);
' "$PROJECT_DIR/vite.config.ts" "$WORK_DIR/vite.config.ts"

echo "=== [2/4] 启动 Vite 前端服务 (http://localhost:1420) ==="
(cd "$WORK_DIR" && bun "$WORK_DIR/node_modules/vite/bin/vite.js" --port 1420) &
VITE_PID=$!

cleanup() {
    echo "正在退出并清理进程..."
    kill $VITE_PID 2>/dev/null || true
}
trap cleanup EXIT INT TERM

# 等待 Vite 启动
echo "等待前端服务就绪..."
for i in {1..30}; do
    if curl -s http://localhost:1420 >/dev/null 2>&1; then
        echo "前端服务已就绪！"
        break
    fi
    sleep 0.5
done

echo "=== [3/4] 配置 Rust 编译缓存目录 ($TARGET_DIR) ==="
export CARGO_TARGET_DIR="$TARGET_DIR"
export PATH="$WORK_DIR/node_modules/.bin:$HOME/.cargo/bin:$PATH"

echo "=== [4/4] 启动 Tauri 桌面应用 ==="
cd "$PROJECT_DIR"
cargo tauri dev -c '{"build": {"beforeDevCommand": ""}}'
```

## 五、日常使用与维护

### 1. 日常启动
在项目根目录下直接执行：
```bash
./run-linux.sh
```
- 首次执行会自动在 `/tmp/reinagent` 完成编译；
- 后续启动会复用缓存，秒级唤起 Tauri 桌面应用。

### 2. 清理重构
若需完全清理本地环境并重新构建，可执行：
```bash
rm -rf /tmp/reinagent
./run-linux.sh
```
